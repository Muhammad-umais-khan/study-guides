01. Tree basics and terminology (L08)

FormalA tree is a finite, non-empty collection of nodes: one designated root, and the rest split into disjoint subtrees T1…Tk, each itself a tree. A tree of n nodes has exactly n−1 edges and exactly one path from the root to any node.

LaymanArrays and linked lists are flat lines. They cannot say “one boss, many reports.” A tree can: every item has one parent above it and any number of children below it.

AnalogyA university org chart: the Chancellor is the root, vice-chancellors report to the Chancellor, campus directors to them, and so on. Unlike a family tree, nobody has two bosses, and the root sits at the top.

Formula decoderedges = n − 1: every node except the root owns exactly one edge up to its parent, so 7 nodes give 6 edges. depth(root) = 0, height(leaf) = 0, height(empty) = −1 (edge-count convention).

Used in: file systems (ls -R is preorder), the HTML DOM, compiler ASTs (3+4*5 becomes a tree), database B-trees.

02. Binary trees and core recursive algorithms (L08 + Lab 09)

FormalA binary tree has at most two children per node (left, right); the empty tree is valid. Strict/Full/Proper: every node has 0 or 2 children. Perfect: every internal node has 2 children and all leaves share one depth. Complete: every level full except the last, which fills left to right.

LaymanBinary just means “at most two kids.” The shape names tell you how tidy the tree is: perfect is a neat triangle, complete has no gaps from the left, full never has a lonely child, skewed is a stick.

AnalogyA tournament bracket. A perfect bracket has all rounds full. A complete bracket has the last round filling from the left. A skewed bracket is a queue where one player faces a new opponent each round.

Formula decoderMax nodes at depth d: 2d (depth 3 gives 8). Max nodes at height h: 2h+1 − 1 (h = 2 gives 7). Min height for n nodes: ⌊log2 n⌋ (n = 10 gives 3). Max height: n−1. Full tree: L = I + 1 (4 leaves, 3 internal).

Java: Node and all six Lab Week 09 algorithms (edge-count height)

class Node { int data; Node left, right;           // data and two child links
  Node(int d) { data = d; } }                        // left/right start as null
class BinaryTree { Node root;
  boolean isUnivalued(Node n) { return n == null || uni(n, n.data); } // empty tree = true (lab rule)
  boolean uni(Node n, int v) {
    if (n == null) return true;                      // nothing left to violate
    if (n.data != v) return false;                   // mismatch: stop early
    return uni(n.left, v) && uni(n.right, v); }    // both subtrees must match
  int tilt = 0;                                      // running total of node tilts
  int findTilt(Node r) { tilt = 0; sum(r); return tilt; } // reset, then ONE postorder pass
  int sum(Node n) {
    if (n == null) return 0;                         // missing child sums to 0
    int l = sum(n.left), r = sum(n.right);           // children first: postorder
    tilt += Math.abs(l - r);                         // this node's tilt
    return l + r + n.data; }                         // subtree sum handed to the parent
  List<String> binaryTreePaths(Node r) {
    List<String> out = new ArrayList<>();
    if (r != null) walk(r, new StringBuilder(), out); return out; }
  void walk(Node n, StringBuilder sb, List<String> out) {
    int len = sb.length();                           // remember length so we can undo
    sb.append(n.data);                               // add this node
    if (n.left == null && n.right == null) out.add(sb.toString()); // leaf: path complete
    else { sb.append("->");                          // otherwise continue down
      if (n.left != null) walk(n.left, sb, out);
      if (n.right != null) walk(n.right, sb, out); }
    sb.setLength(len); }                             // backtrack: next path starts clean
  Node invertTree(Node n) {
    if (n == null) return null;                      // base case
    Node t = n.left;                                 // keep left before overwriting it
    n.left = invertTree(n.right);                    // right becomes left, inverted
    n.right = invertTree(t);                         // old left becomes right, inverted
    return n; }                                      // every node swapped, not just root
  boolean isBalanced(Node r) { return ht(r) != -2; } // -2 is the "unbalanced" marker
  int ht(Node n) {
    if (n == null) return -1;                        // empty = -1, so a leaf = 0
    int l = ht(n.left);  if (l == -2) return -2;     // pass failure straight up
    int r = ht(n.right); if (r == -2) return -2;
    if (Math.abs(l - r) > 1) return -2;              // this node is unbalanced
    return 1 + Math.max(l, r); }                     // edge-count height
}

What breaks: recomputing sums inside findTilt makes it O(n²). Skipping setLength leaks one path into the next. Overwriting n.left before saving it loses a subtree. Returning a plain boolean from ht forces repeated height scans. All are O(n) time and O(h) stack.

03. Traversals and expression trees (L08 + Lab 09)

FormalTraversal visits every node exactly once (search may stop early). Depth-first: preorder N-L-R, inorder L-N-R, postorder L-R-N. Breadth-first: level order with a queue. Each is O(n) time and O(h) stack (O(width) queue for BFS).

LaymanThe only difference is when you write down a node: before its kids, between them, or after them. Inorder on a general tree is not sorted; it is sorted only for a BST.

AnalogyCleaning a building with rooms inside rooms. Preorder: note the room, then enter. Postorder: clean the inner rooms first, then the outer one (deleting a folder). Level order: sweep floor by floor.

Formula decoderTree 1,2,3,4,5 (2 has kids 4,5). Pre: 1 2 4 5 3. In: 4 2 5 1 3. Post: 4 5 2 3 1. Level: 1 2 3 4 5.

Java: four traversals

void pre(Node n)  { if (n == null) return;           // base case ends recursion
  System.out.print(n.data + " ");                    // visit BEFORE children
  pre(n.left); pre(n.right); }
void in(Node n)   { if (n == null) return;
  in(n.left);                                        // dive to the deepest left first
  System.out.print(n.data + " ");                    // visit BETWEEN children
  in(n.right); }
void post(Node n) { if (n == null) return;
  post(n.left); post(n.right);                       // children resolved first
  System.out.print(n.data + " "); }                  // visit AFTER children
void level(Node r) { if (r == null) return;
  Queue<Node> q = new LinkedList<>(); q.add(r);      // queue holds the frontier
  while (!q.isEmpty()) {
    Node n = q.remove();                             // oldest node first (FIFO)
    System.out.print(n.data + " ");
    if (n.left != null) q.add(n.left);               // enqueue kids for the next level
    if (n.right != null) q.add(n.right); } }

What breaks: a stack instead of a queue gives preorder-like order, not levels. Forgetting the null checks before q.add crashes later.

04. Priority queues and binary heaps (L09)

FormalThe Priority Queue ADT specifies insert, peek/getMax, extractMax and isEmpty/size. The binary heap is one implementation: a complete binary tree (shape property) where Key(parent) ≥ Key(child) in a max-heap, ≤ in a min-heap (heap-order property). Invented by J. W. J. Williams (1964). Height is ⌊log2 n⌋.

LaymanA normal queue serves first come, first served, which is fatal in a hospital. A priority queue always serves the most urgent item. A heap is the cheap way to build one: biggest at the top, nothing else fully sorted.

AnalogyEmergency-room triage: the cardiac arrest jumps ahead of the headache. The ADT is the promise (“serve the sickest”); the heap is the actual waiting-room layout that keeps the promise cheaply.

Formula decodern inserts into an unsorted or sorted array cost O(n²) in total; a heap costs O(log n) each, so O(n log n). Height ⌊log2 n⌋: 7 items stack 3 levels, so any insert moves at most 2 steps.

ImplementationinsertextractMaxpeek
Unsorted arrayO(1)O(n)O(n)
Sorted arrayO(n)O(1)O(1)
Balanced BSTO(log n)O(log n)O(log n)

Heap vs BST: a BST orders horizontally (left < root < right). A heap orders vertically only (parent ≥ child); siblings have no order, so a left child can be larger than the right. Heap vs JVM heap: the JVM heap is an unstructured memory pool for new; the heap data structure is an array-stored tree. They share a name by accident.

Min-heap dual: the same code with the comparison reversed, so smallest replaces largest and the root holds the minimum.

Applications: OS scheduling (Linux CFS), Dijkstra and Prim (min-heap), Huffman coding (merge two least frequent), streaming top-K (min-heap of size K), k-way merge in external sort (min-heap of size k).

05. Array-based heap operations and index math

FormalA binary max-heap is a complete binary tree (shape property) where every node is ≥ its children (heap-order property). Stored in an array with no pointers.

LaymanA heap does one job well: the biggest item is always at the top, and you can grab it instantly. Items fill the tree left to right, level by level, so the tree can live in a plain array and you find relatives with arithmetic.

AnalogyAn emergency-room waiting list. The most critical patient is always at the front desk. A new arrival sits at the back, then swaps upward past anyone less urgent (siftUp). When the front patient is treated, the person at the very back steps up and swaps downward with the more urgent of the two people below (siftDown).

Formula decoderparent(i) = ⌊(i−1)/2⌋, left(i) = 2i+1, right(i) = 2i+2. For i = 4: parent = ⌊3/2⌋ = 1; children = 9 and 10. First leaf = ⌊n/2⌋; last internal = ⌊n/2⌋−1. With n = 6 the first leaf is index 3.

Java: MaxHeap insert and extractMax

class MaxHeap {
  int[] a = new int[8]; int n = 0;                  // 0-based array; n = number of items
  void insert(int v) {
    if (n == a.length) a = java.util.Arrays.copyOf(a, n * 2); // full: double capacity (amortized O(1))
    a[n] = v; int i = n++;                          // put at next free slot: keeps the tree complete
    while (i > 0 && a[(i-1)/2] < a[i]) {         // siftUp: while bigger than parent...
      swap(i, (i-1)/2); i = (i-1)/2; }              // ...swap up and move to the parent index
  }
  int extractMax() {
    int top = a[0]; a[0] = a[--n];                  // save max; move LAST leaf to the root
    int i = 0;
    while (2*i + 1 < n) {                           // siftDown: loop while a left child exists
      int c = 2*i + 1;                              // c = left child
      if (c + 1 < n && a[c+1] > a[c]) c++;        // choose the LARGER child
      if (a[i] >= a[c]) break;                      // order restored: stop
      swap(i, c); i = c; }                          // otherwise swap down and continue
    return top; }
  void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}

What breaks: swapping with the smaller child in siftDown breaks heap order. Dropping c + 1 < n reads a stale slot. Using n * 2 before the length check overruns the array. Floyd buildHeap runs siftDown from index ⌊n/2⌋−1 down to 0 and costs O(n), because most nodes sit near the leaves.

06. Floyd buildHeap and in-place HeapSort (L09 + Lab 10 Task 8)

FormalFloyd’s buildHeap (1964) turns any array into a max-heap in O(n) by running siftDown for i = ⌊n/2⌋−1 down to 0. HeapSort = buildHeap, then repeatedly swap arr[0] with arr[heapSize], shrink the heap, and siftDown the root. Time O(n log n) in every case, extra space O(1), not stable.

LaymanLeaves are already tiny valid heaps, so skip them. Start at the last parent and fix each parent from the bottom up. To sort, keep pulling the biggest to the end of the array and re-fix the shrinking heap.

AnalogyA company reshuffle that starts with the lowest managers. Each manager swaps places with their stronger report until order holds. Then the CEO is sent to the back of the line (final position) and a new CEO is chosen from the rest.

Formula decoderNodes at height k number about n/2k+1, each costing k swaps: ∑ k·n/2k+1 ≤ (n/2)∑ k/2k = (n/2)·2 = n. So O(n), not O(n log n): half the nodes cost 0, a quarter cost 1.

Java: HeapSort (Lecture 09 version)

public static void sort(int[] arr) {
  int n = arr.length;
  for (int i = n / 2 - 1; i >= 0; i--)               // Phase 1: last parent down to root
    siftDown(arr, i, n);                             // leaves skipped: already valid heaps
  for (int size = n - 1; size > 0; size--) {         // Phase 2: shrink the heap one by one
    int t = arr[0]; arr[0] = arr[size]; arr[size] = t; // max goes to its FINAL slot
    siftDown(arr, 0, size); } }                      // repair only 0..size-1, not the full array
static void siftDown(int[] a, int i, int n) {
  while (true) {
    int largest = i, l = 2 * i + 1, r = 2 * i + 2;   // 0-based children
    if (l < n && a[l] > a[largest]) largest = l;    // bounds check BEFORE reading a[l]
    if (r < n && a[r] > a[largest]) largest = r;    // largest of parent, left, right
    if (largest == i) break;                         // heap order holds: stop
    int t = a[i]; a[i] = a[largest]; a[largest] = t; // swap with the LARGER child
    i = largest; } }                                 // continue from the child’s slot

What breaks: using n instead of size in phase 2 re-sifts sorted elements back in. Starting buildHeap at n-1 wastes work; starting above n/2-1 is fine but unnecessary.

07. BST: search, insert and queries (L10 + Lab 10 Tasks 1–5)

FormalIn a BST, for every node x, all keys in the left subtree are < x and all keys in the right subtree are > x (the whole subtree, not just the children). Inorder traversal therefore yields sorted keys: a node sits between its left and right subtree values. Search/insert take O(h). Duplicate policy (this course): reject. Alternatives are a count field or a linked list at the node.

LaymanEvery comparison throws away half the tree: smaller means go left, larger means go right. Inserting is just searching until you fall off the tree, then hanging the new node there.

AnalogyA library with signs at every junction: “titles A–M left, N–Z right.” You never walk both ways. A new book is shelved where the search for it would have ended.

Formula decoderBalanced: h = ⌊log2 n⌋, so 45,000 items need about 16 steps. Sorted insertion: h = n−1 = 44,999 steps (a chain). Range sum low = 7, high = 15 skips the left subtree when the key is below 7.

Java: BST operations and Lab Week 10 queries

boolean search(Node n, int k) {
  if (n == null) return false;                       // fell off a null link: absent
  if (k == n.data) return true;                      // match
  return k < n.data ? search(n.left, k) : search(n.right, k); } // only ONE side per step
boolean searchIt(int k) { Node c = root;             // iterative: O(1) stack
  while (c != null) { if (k == c.data) return true; c = k < c.data ? c.left : c.right; }
  return false; }
Node insert(Node n, int k) {
  if (n == null) return new Node(k);                 // empty spot found: new leaf
  if (k < n.data) n.left = insert(n.left, k);        // go left and re-link
  else if (k > n.data) n.right = insert(n.right, k); // go right and re-link
  return n; }                                        // equal key: do nothing (reject)
Node findMin(Node n) { while (n.left != null) n = n.left; return n; }   // leftmost
Node findMax(Node n) { while (n.right != null) n = n.right; return n; } // rightmost
Node searchBST(Node n, int v) {                      // returns the SUBTREE root or null
  while (n != null && n.data != v) n = v < n.data ? n.left : n.right;
  return n; }
boolean findTarget(Node r, int k) { return two(r, k, new HashSet<>()); }
boolean two(Node n, int k, Set<Integer> seen) {
  if (n == null) return false;
  if (seen.contains(k - n.data)) return true;        // complement was a DIFFERENT earlier node
  seen.add(n.data);                                  // add AFTER checking: no self-pairing
  return two(n.left, k, seen) || two(n.right, k, seen); }
// Two-pointer variant: list = inorder keys, i = 0, j = size-1
// while (i < j) { int s = list[i] + list[j]; if (s == k) return true; if (s < k) i++; else j--; }
int rangeSumBST(Node n, int lo, int hi) {
  if (n == null) return 0;
  if (n.data < lo) return rangeSumBST(n.right, lo, hi); // too small: whole left subtree out
  if (n.data > hi) return rangeSumBST(n.left, lo, hi);  // too big: whole right subtree out
  return n.data + rangeSumBST(n.left, lo, hi) + rangeSumBST(n.right, lo, hi); } // endpoints included

Two exam perspectives: Lab 10 rejects duplicates, which is what the code above does. Lecture 10’s insert slide sends keys greater than or equal to the node to the right subtree, so it keeps duplicates. Always follow the policy stated in the question.

What breaks: checking only children (not whole subtrees) accepts invalid trees. Adding to the set before checking pairs a node with itself (k = 2 × value). HashSet: O(n) time, O(n) space; two pointers: O(n) time, O(n) space for the list. Range sum visits only the v nodes it cannot prune.

08. BST deletion, degeneracy and complete-tree counting (L10 + Lab 10 Tasks 1 and 6)

FormalDelete first finds the node, then: leaf → return null to the parent; one child → return that child (bypass); two children → copy the in-order predecessor (max of left subtree) or successor (min of right subtree) into the node, then delete that copy, which has at most one child. A BST is balanced at h = ⌊log2 n⌋ and degenerate at h = n−1; sorted or reverse-sorted insertion always gives the degenerate case.

LaymanRemoving a leaf is trivial. A node with one child just lets that child take its place. A node with two children cannot leave a hole, so you borrow the closest value in sorted order, which is always safe to put there.

AnalogyA retiring manager with two teams: you promote the best member of the left team (the largest value below them). Order is preserved and the promoted person’s old seat is easy to refill.

Formula decoderComplete tree with equal leftmost and rightmost node-heights h is perfect: count = 2h − 1 (h = 3 gives 7). Cost O(log² n): about log n levels of recursion, each measuring heights in O(log n).

Node delete(Node n, int k) {
  if (n == null) return null;                        // key absent: nothing to do
  if (k < n.data) n.left = delete(n.left, k);        // search left
  else if (k > n.data) n.right = delete(n.right, k); // search right
  else {                                             // found the node
    if (n.left == null) return n.right;              // leaf or right child only: bypass
    if (n.right == null) return n.left;              // left child only: bypass
    Node p = findMax(n.left);                        // two kids: predecessor
    n.data = p.data;                                 // copy its value up
    n.left = delete(n.left, p.data); }               // remove the original (leaf/1 child)
  return n; }                                        // re-link on the way back
int countNodes(Node r) {                             // complete tree only, node-count height
  if (r == null) return 0;
  int lh = 0, rh = 0;
  for (Node a = r; a != null; a = a.left)  lh++;     // leftmost path length
  for (Node b = r; b != null; b = b.right) rh++;     // rightmost path length
  if (lh == rh) return (1 << lh) - 1;               // perfect: 2^h - 1, no recursion
  return 1 + countNodes(r.left) + countNodes(r.right); } // else one side is perfect

What breaks: forgetting n.left = delete(...) never re-links. Deleting the copy from the wrong subtree removes the wrong key. Using countNodes on a non-complete tree gives wrong counts because equal edge heights no longer imply a perfect tree. Tests: [1,2,3,4,5,6] gives 6; empty gives 0; [1] gives 1.

09. Balanced BSTs and AVL trees

FormalAn AVL tree is a BST in which every node has balance factor BF = height(left) − height(right) ∈ {−1, 0, +1}. After an insert or delete, walk up; at the first node with |BF| = 2, rotate. Height is at most 1.44 log2 n, so search, insert and delete are O(log n).

LaymanA plain BST can turn into a linked list if you insert sorted data. AVL stops that: after each insert it checks the path back to the root, and if one side has become two levels taller than the other, it rotates a few pointers to even things out.

AnalogyA hanging mobile. If one arm gets too heavy, you do not rebuild it. You lift the heavy arm’s middle piece up to become the new pivot, and the old pivot hangs below on the lighter side.

Formula decoderBF(x) = h(left) − h(right). Insert 30, 20, 10: node 30 has h(left) = 2 (node-count) and h(right) = 0, so BF = +2. The new key went left-left, so rotate right at 30.

Java: AVLTree rotations and insert (node-count height)

class AVLTree {
  class Node { int key, h = 1; Node l, r; Node(int k) { key = k; } } // new leaf has height 1
  Node root;
  int h(Node n)  { return n == null ? 0 : n.h; }          // null has height 0
  int bf(Node n) { return n == null ? 0 : h(n.l) - h(n.r); } // balance factor
  void fix(Node n) { n.h = 1 + Math.max(h(n.l), h(n.r)); }   // recompute height from children
  Node rotR(Node x) {                                     // x = unbalanced node (case LL)
    Node w = x.l;                                         // w becomes the new subtree root
    x.l = w.r;                                            // w's right subtree moves under x
    w.r = x;                                              // x drops to w's right
    fix(x); fix(w);                                       // x first (now lower), then w
    return w; }                                           // caller links parent to w
  Node rotL(Node w) { Node x = w.r; w.r = x.l; x.l = w; fix(w); fix(x); return x; } // mirror
  Node insert(Node n, int k) {
    if (n == null) return new Node(k);                    // empty spot: create leaf
    if (k < n.key) n.l = insert(n.l, k);                  // go left
    else if (k > n.key) n.r = insert(n.r, k);             // go right
    else return n;                                        // duplicate: reject
    fix(n);                                               // update height on the way up
    int b = bf(n);                                        // check EVERY ancestor
    if (b > 1 && k < n.l.key) return rotR(n);           // LL
    if (b < -1 && k > n.r.key) return rotL(n);          // RR
    if (b > 1)  { n.l = rotL(n.l); return rotR(n); }      // LR: two rotations
    if (b < -1) { n.r = rotR(n.r); return rotL(n); }      // RL: two rotations
    return n; }                                           // balanced: unchanged
  void add(int k) { root = insert(root, k); }             // always re-assign root: it may change
}

What breaks: calling fix(w) before fix(x) leaves w with a stale height. Forgetting root = insert(...) loses a rotated root. Using edge-count height here would make a leaf 0 and shift every BF check. Keep one convention per program.

10. Hashing and collision resolution

FormalA hash table maps key k to slot h(k) in an array of size M. Load factor α = N/M. Collisions are resolved by separate chaining (a list per slot) or open addressing (probe for another slot: linear, quadratic, double hashing). Expected O(1) search and insert while α stays small.

LaymanYou cannot make an array as big as every possible key (a CNIC has 13 digits). So you squash each key into a small number with a formula and use that number as the shelf. Two keys sometimes land on the same shelf, and you need a rule for that.

AnalogyPost-office pigeonholes. Chaining: each pigeonhole holds a stack of letters. Open addressing: if your hole is taken, you walk to the next free hole, which means a letter taken out must leave a “was here” marker, or later searches stop too early.

Formula decoderh(k) = k mod M: 44 mod 11 = 0, 88 mod 11 = 0, so they collide. h = (h×31 + c) mod M is Horner’s rule: it uses character position, so ‘stop’ and ‘pots’ differ, while a plain ASCII sum gives the same value for both.

Java: polynomial hash and linear probing with tombstones

// state[]: 0 = EMPTY, 1 = OCCUPIED, 2 = DELETED (tombstone); table[] holds ints; M = size
int hash(String s, int M) {
  long h = 0;
  for (char c : s.toCharArray()) h = (h * 31 + c) % M;   // Horner: shift old value, add new char
  return (int) h; }
boolean put(int k) {
  int t = -1;                                            // first tombstone seen
  for (int p = 0; p < M; p++) {                          // at most M probes
    int j = (k % M + p) % M;                             // linear probe sequence
    if (state[j] == 1 && table[j] == k) return false;  // duplicate: reject
    if (state[j] == 2 && t < 0) t = j;                // remember first reusable slot
    if (state[j] == 0) {                                 // EMPTY ends the search
      int s = (t < 0) ? j : t; table[s] = k; state[s] = 1; return true; } }
  if (t >= 0) { table[t] = k; state[t] = 1; return true; }
  return false; }                                        // table full

What breaks: marking a deleted slot EMPTY cuts the probe chain so later keys look absent. Stopping at a tombstone during search misses keys beyond it. Rehash by re-inserting every key into a table of about 2M (prime) slots: copying positions fails because h depends on M.

11. Sorting foundations and elementary sorts

FormalAn inversion is a pair i < j with A[i] > A[j]. An array is sorted iff it has 0 inversions; the maximum is n(n−1)/2. An adjacent swap or an insertion shift removes exactly one inversion, so insertion sort runs in Θ(n + I) for I inversions.

LaymanSorting means fixing every pair that is in the wrong order. Elementary sorts fix them one neighbor at a time, which is fine for small or almost-sorted data and slow for big data.

AnalogySorting playing cards in your hand: pick up the next card, slide the bigger cards one place right, and drop the card into the gap. If the hand is nearly sorted, you barely slide anything.

Formula decoderI = n(n−1)/2 for reverse order: n = 5 gives 10, so [9,7,5,3,1] needs 10 comparisons and 10 shifts in insertion sort. [1,2,3,5,4] has I = 1.

Lab Week 08 Task 1: counted insertion sort

static void insertion(int[] a) {
  int cmp = 0, shifts = 0;                         // define counting rules up front
  for (int i = 1; i < a.length; i++) {             // a[0..i-1] is already sorted
    int key = a[i], j = i - 1;                     // key = card to insert
    while (j >= 0) {
      cmp++;                                       // count every key comparison
      if (a[j] <= key) break;                      // <= keeps equal keys in order (stable)
      a[j + 1] = a[j]; shifts++; j--; }            // shift bigger value right
    a[j + 1] = key; }                              // drop key into the gap
  System.out.println("cmp=" + cmp + " shifts=" + shifts);
}

Traversals and tree measures (edge-count height)

void pre(Node n){ if(n==null) return; visit(n); pre(n.left); pre(n.right); }
void in(Node n){ if(n==null) return; in(n.left); visit(n); in(n.right); }
void post(Node n){ if(n==null) return; post(n.left); post(n.right); visit(n); }
void level(Node r){ if(r==null) return; Queue<Node> q=new LinkedList<>(); q.add(r);
  while(!q.isEmpty()){ Node n=q.remove(); visit(n);
    if(n.left!=null) q.add(n.left); if(n.right!=null) q.add(n.right); } }
int count(Node n){ return n==null?0:1+count(n.left)+count(n.right); }
int leaves(Node n){ if(n==null) return 0; if(n.left==null&&n.right==null) return 1; return leaves(n.left)+leaves(n.right); }
int height(Node n){ return n==null?-1:1+Math.max(height(n.left),height(n.right)); }
int chk(Node n){ if(n==null) return -1; int l=chk(n.left); if(l==-2) return -2;
  int r=chk(n.right); if(r==-2||Math.abs(l-r)>1) return -2; return 1+Math.max(l,r); }
boolean isBalanced(Node r){ return chk(r)!=-2; }

Line by line: the null check is the base case; visit position (before, between, after the two calls) is the only difference between the three orders. Level order swaps recursion for a queue. chk returns height or the sentinel −2 so each node is visited once: O(n).

What breaks: a missing null check gives a NullPointerException. Returning 0 for null makes leaf height 1 (wrong convention here). Calling height inside isBalanced at every node gives O(n²). Using a stack instead of a queue gives a different order.

BST search, insert, min, max

Node search(Node n,int k){ if(n==null||n.key==k) return n; return k<n.key?search(n.left,k):search(n.right,k); }
Node searchI(Node n,int k){ while(n!=null&&n.key!=k) n=k<n.key?n.left:n.right; return n; }
Node insert(Node n,int k){ if(n==null) return new Node(k);
  if(k<n.key) n.left=insert(n.left,k); else if(k>n.key) n.right=insert(n.right,k); return n; }
Node findMin(Node n){ while(n.left!=null) n=n.left; return n; }
Node findMax(Node n){ while(n.right!=null) n=n.right; return n; }

Each step discards one whole subtree. n.left=insert(...) reattaches the (possibly new) child. The else if rejects duplicates (Lab Week 10); the Lecture 10 slide sends equal keys right instead (else).

What breaks: writing insert(n.left,k); without assigning loses the new node. Calling findMin(null) crashes. Searching a skewed tree is O(n).

Max-heap siftUp / siftDown (0-based) and AVL rotations (node-count height)

void siftUp(int[] a,int i){ while(i>0){ int p=(i-1)/2; if(a[p]>=a[i]) break; swap(a,p,i); i=p; } }
void siftDown(int[] a,int n,int i){ while(2*i+1<n){ int c=2*i+1;
    if(c+1<n&&a[c+1]>a[c]) c++; if(a[i]>=a[c]) break; swap(a,i,c); i=c; } }
int h(Node n){ return n==null?0:n.h; }
void fix(Node n){ n.h=1+Math.max(h(n.left),h(n.right)); }
Node rotateRight(Node y){ Node x=y.left; y.left=x.right; x.right=y; fix(y); fix(x); return x; }
Node rotateLeft(Node x){ Node y=x.right; x.right=y.left; y.left=x; fix(x); fix(y); return y; }

siftDown picks the larger child (c++) and stops when the parent is already ≥ it. In a rotation the pivot moves up, the pivot's inner subtree changes parent, then heights are fixed bottom-up: old root first, new root second.

What breaks: swapping with the smaller child, dropping c+1<n, fixing the new root before the old one (stale height), forgetting to return and assign the new subtree root.

14C. Lab viva bank

Compiled from this guide's lab sections.

Why is HeapSort not stable?
Swapping the root with the last element moves equal keys across long distances, so their original order can flip.

Why is Floyd buildHeap O(n) and not O(n log n)?
Half the nodes are leaves and sift zero levels; the sum over levels of k/2^k converges to a constant.

How do you delete a BST node with two children?
Copy max(left) or min(right) into it, then delete that donor, which has at most one child.

What does inorder traversal of a BST give?
Keys in sorted order; this is also how you validate a BST.

Why is isBalanced O(n) bottom-up but O(n²) top-down?
Top-down recomputes subtree heights at every node; bottom-up returns height and balance together in one pass.

When does an AVL tree need a double rotation?
When the heavy child leans the opposite way (LR or RL): rotate the child first, then the unbalanced node.

Why does the AVL lab use node-count height?
null = 0 and leaf = 1 let h(null) work without a special case; keep one convention per program.

What is the cost of a bad BST?
Sorted insertion makes a chain of height n−1, so search, insert and delete are O(n).

Which elementary sort is best on nearly sorted data and why?
Insertion sort (or flagged bubble): work is about n plus the inversion count.

Why a tombstone instead of EMPTY on delete?
EMPTY ends a probe chain, so later keys in the chain become unreachable.

Two-Sum in a BST (findTarget): what are the two approaches?
HashSet: visit each node and check whether k minus its value is already in the set. O(n) time, O(n) space. Inorder plus two pointers: inorder gives a sorted list in O(n), then move the pointers inward. O(n) time and O(n) space for the list.

How does rangeSumBST avoid visiting the whole tree?
If node.val < low, all left descendants are below the range, so skip the left subtree. If node.val > high, skip the right subtree. Only boundary paths and in-range nodes are visited.

Why is countNodes on a complete tree O(log2 n) and not O(n)?
Leftmost and rightmost heights each cost O(log n). If they match, the subtree is perfect: return 2h − 1 at once. Otherwise one child is perfect, so only one path recurses: about log n levels of O(log n) work.

Why does search(root, k) return boolean while searchBST(root, val) returns a Node?
The boolean version only reports presence. The Node version returns the matching subtree root (or null), so the caller can read or change it. Both take O(h) time.

Why does AVL insertion need at most one rotation fix, but deletion may need O(log n)?
After an insert, the first unbalanced ancestor regains its old height after one single or double rotation, so higher nodes are unaffected. A delete can shrink a subtree and push imbalance upward, so rotations can repeat along the path: up to O(log n).

Top 30 exam-winning facts and convention traps

  1. Edge-count height: empty −1, leaf 0. AVL and Lab 10 countNodes: null 0, leaf 1.
  2. Heaps here are 0-based: kids 2i+1, 2i+2.
  3. Last internal node is ⌊n/2⌋−1.
  4. Preorder first item is the root; the last postorder item is the root.
  5. Pre + In (or Post + In) rebuilds a unique tree; Pre + Post does not.
  6. Inorder of a BST is sorted.
  7. Level order uses a queue.
  8. Edges = n − 1.
  9. Full tree: leaves = internal + 1.
  10. Check the whole subtree for BST validity, not only children.
  11. Two-child delete: max(left) or min(right).
  12. Lab 10 rejects duplicates; Lecture 10 sends them right.
  13. Sorted insertions make a skewed BST of height n−1.
  14. siftDown swaps with the larger child (max-heap).
  15. insert = place last, siftUp; extractMax = last to root, siftDown.
  16. buildHeap is O(n); n inserts are O(n log n).
  17. HeapSort: build, then swap root with the end and shrink; unstable, in place.
  18. AVL single rotation when child sign matches (LL, RR); double when it differs (LR, RL).
  19. Fix the lower node's height first in a rotation.
  20. One insertion needs at most one rotation fix; deletion may need many.
  21. Always use root = insert(root, k).
  22. Hash home slot is k mod M; compute it before probing.
  23. Linear probing: +1, +2, ... mod M; primary clustering.
  24. Double hashing step h2 must never be 0.
  25. Delete in open addressing writes DELETED, never EMPTY.
  26. Search skips DELETED; insert may reuse the first DELETED after confirming the key is absent.
  27. Rehash re-inserts every key; positions depend on M.
  28. Inversions: n(n−1)/2 max; 0 means sorted.
  29. Stable: bubble, insertion. Not stable: selection, heap.
  30. Bubble with isSwapped exits after a pass with no swaps (best case O(n)).
